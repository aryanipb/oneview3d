One-View 3D Completion

One scan file in, one completed object out. A depth sensor only sees the front of an object. This app finds the object in a single scan file and predicts its full 3D shape, including the hidden back. It never combines several files. Everything runs on your device; nothing is uploaded.

About

One file, one object. The model gets a single scan file and returns one completed object. Files are never fused, and the sample labels (“Red bottle”, “Blue bottle”, “Box”) are only what the person who scanned them said they show: they are not given to the model and are not predictions.

The model is AdaPoinTr (Yu et al., IEEE TPAMI 2023), starting from the authors’ official PCN weights and fine-tuned only on simulated hand-held time-of-flight scans with their true complete shapes. The 10 real sample scans are a test set: they were never used for training, tuning or model selection.

What the file keeps and what it loses. The device exports 4096 points centred and divided by the largest coordinate, so the metric size and distance are gone and cannot be recovered. What survives is the geometry seen from the sensor: the background wall shows the sensor’s 8 columns as stripes at known angles, which locates the sensor inside the file. From that the page derives the object’s distance relative to the background and its angular size, and puts the object in a distance-consistent frame (“object-distance units”, not centimetres) before the model sees it. The same preprocessing code runs here and in Python, and ?selftest checks they agree.

Limits. The real scans were taken from one viewpoint with the object held very close, so each file sees only a small patch of the object (a few hundred noisy points), and hand motion smears it. Completions of real scans are therefore rough and can be wrong; the hidden back is always a prediction, never a measurement. The distance and angle estimates are approximate and are marked “not recoverable” whenever the stripes cannot be fitted.
